# Scaling Guide

## Formula

```
Max concurrent sink calls = goose_pods × workers_per_pod
                              (capped by Kafka partitions)

Max throughput = concurrent_calls × (1000 / endpoint_latency_ms)
```

## Example Configurations

| Partitions | Pods | Workers | Latency | Throughput |
|-----------|------|---------|---------|------------|
| 3 | 3 | 50 | 100ms | ~1,500/s |
| 10 | 10 | 50 | 100ms | ~5,000/s |
| 10 | 10 | 50 | 5ms | ~100,000/s |
| 50 | 50 | 50 | 100ms | ~25,000/s |

## K8s Resource Limits

```yaml
resources:
  requests:
    cpu: 200m
    memory: 64Mi
  limits:
    cpu: 500m
    memory: 128Mi
```

## Checklist

- [ ] Kafka partitions ≥ desired max pods
- [ ] `SINK_WORKER_POOL_SIZE` matches CPU limits
- [ ] `SINK_HTTP_MAX_CONNECTIONS` = `SINK_WORKER_POOL_SIZE` (auto-matched)
- [ ] `MAX_POLL_RECORDS × HTTP_latency < max.poll.interval_ms`
