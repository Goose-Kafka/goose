Sink Types
// SINKS

Five sinks. One binary.

Each Goose deployment targets one sink type. Pluggable via the Sink interface — add your own without touching the core.

🌐

HTTP REST

Individual, batch, and batch-with-response modes. Connection TTL prevents pod pinning. Configurable per-status-code error routing.

SINK_TYPE=http
⚡

gRPC

Raw protobuf passthrough — no Stencil or schema registry needed. gRPC error codes auto-classified as permanent or transient.

SINK_TYPE=grpc
🍃

MongoDB

Insert and upsert modes. Duplicate key errors (code 11000) auto-routed to DLQ. JSON fields become BSON documents.

SINK_TYPE=mongodb
🐘

PostgreSQL

INSERT and ON CONFLICT upsert. JSON fields auto-mapped to columns. Connection pooling with configurable max connections.

SINK_TYPE=postgresql
🔴

Redis

KeyValue, hashset, and list data types. Key templating from message fields. TTL support. Standalone and cluster deployment.

SINK_TYPE=redis

Running in under 2 minutes

One Docker image. One Helm chart. All config via environment variables.

# Docker

terminal
# Pull the image docker pull ghcr.io/goose-kafka/goose:latest # Run with 4 env vars docker run \ -e SOURCE_KAFKA_BROKERS=kafka:9092 \ -e SOURCE_KAFKA_TOPIC=events \ -e SOURCE_KAFKA_CONSUMER_GROUP_ID=goose \ -e SINK_HTTP_SERVICE_URL=http://svc:8080/api \ ghcr.io/goose-kafka/goose:latest

# Kubernetes (Helm)

terminal
# Clone the repo git clone https://github.com/Goose-Kafka/goose cd goose # Deploy to K8s helm install goose ./helm \ --set env.SOURCE_KAFKA_BROKERS=kafka:9092 \ --set env.SOURCE_KAFKA_TOPIC=events \ --set env.SINK_HTTP_SERVICE_URL=http://svc:8080/api # Scale to 4 pods helm upgrade goose ./helm \ --set replicaCount=4
// FEATURES

Built for production

Everything you need to reliably consume Kafka and deliver to your downstream — nothing you don't.

🛡️

At-Least-Once Delivery

Contiguity-gated offset commits. Network errors always retried. Zero message drops.

⚡

Circuit Breaker

Sliding window. Opens on high failure rate. Probes and auto-recovers when sink is back.

🔄

Retry → DLQ → Ignore

Config-driven error routing by HTTP status code. Transient errors retried, permanent → DLQ.

🔗

Connection TTL

Connections closed after TTL and re-opened. Fixes pod pinning — redistributes traffic.

📐

Proto→JSON Conversion

Via Stencil schema registry. Long-polling refresh — hot-swap descriptors without restart.

🔍

CEL Filtering

JEXL-equivalent expressions. AND/OR, IN, has(), startsWith(), size(), nested fields.

✅

Schema Validation

CEL-based validation before delivery. Invalid messages → DLQ. Catch bad data early.

📊

15 Prometheus Metrics

Throughput, latency p50/p95/p99, errors, circuit breaker, consumer lag, HTTP status codes.

🎯

OTel Tracing

firehose.consume + firehose.process_batch spans. Export to Jaeger or Tempo.
